# Plan: settle the (72,108) case of the plane Jacobian Conjecture bound

Goal: discard (or find a live solution for) the last Newton-polygon family below degree 125:
GGV-Horruitiner (arXiv:2204.14178) Prop. 4.3, family A0=(8,28), (m,n)=(3,2), i.e. (deg P, deg Q)=(108,72).

Reduced problem (Prop 4.3): show there are no P,Q in L^(1) with

    [P,Q] = x^2

and Newton polygons
  subcase (1): N(P) = {(0,0),(1,0),(8,14),(8,16),(0,8)},  N(Q) = {(0,0),(2,1),(12,21),(12,24),(0,12)}
  subcase (2): same minus corners (0,8) / (0,12)
with corner coefficients nonvanishing (plus the internal Pred-branches of the §4 proof).

Scale: N(P) contains 61 lattice points, N(Q) 125 → ~186 coefficient unknowns before
normalization; bracket support gives ~350–450 bilinear equations. GGV's canonical system
St(n,m) (arXiv:1406.0886) for this pair is 178 eqns/178 vars; their (50,75) benchmark was
123×123 and "too big" for direct Mathematica solving in their hands.

## Stack (no Mathematica needed)

| Need | Tool (all open source) |
|---|---|
| Custom arithmetic: truncated Laurent series in x^-1 over K[y] with symbolic coeffs, brackets, v_{ρ,σ}, leading forms | Julia + Nemo/AbstractAlgebra (FLINT underneath); alt: SageMath |
| Gröbner engine (F4 + FGLM/RUR), Q and F_p, multithreaded | msolve (primary); Groebner.jl for quick probes |
| Independent GB cross-check | Singular (std/slimgb), Macaulay2 (elimination/saturation) |
| Emptiness certificate 1 = Σ h_i f_i | Singular `lift`; verify with a small standalone FLINT/Nemo checker |
| Solutions branch: exact algebraic numbers | msolve RUR + Hecke/Nemo (or PARI) |
| Numerical cross-check | HomotopyContinuation.jl + `certify` (interval a-posteriori certification) |
| Reproducibility | Nix or Docker image; seeds + prime lists logged; all systems emitted as text |

Mathematica's only role: optionally replaying the authors' original notebooks if they share
them (they used Mathematica's Eliminate). Every function used has a faster open-source
replacement (Eliminate/GroebnerBasis → msolve/Singular; Solve → RUR; series → custom Nemo).

## Phases

### Phase 0 — source recovery (parallel, ~0 effort)
Status check 2026-07-24 (verified by adversarial research pass): no public effort on the
(72,108) case found anywhere — the target is unclaimed.
- Email Valqui / the Guccinones: ask for the stuck system + notebooks for the (8,28) case
  and their modified-bracket St variant ([P,Q]=x^2 ∉ K^×, cf. 1406.0886 §5 remark).
- Collect the dependency chain: 1401.1784 (=J. Algebra 471), 1605.09430, 1406.0886,
  1708.07936, 2204.14178. Note: parts of the chain are arXiv-only (unrefereed) — flag in
  any writeup; our computation relies on Prop 4.3 only.

### Phase 1 — core library (week 1–2)
Objects: F = Σ_{k ≤ k0} x^k f_k(y), f_k ∈ R[y], R ∈ {Q, F_p, poly ring in unknown coeffs}.
Ops: mul, pow, bracket [P,Q] = P_x Q_y − P_y Q_x, v_{ρ,σ}, ℓ_{ρ,σ}, en_{ρ,σ}, truncation mgmt.
Property tests: bracket antisymmetry + Leibniz; v(fg) = v(f)+v(g) on leading forms;
torus equivariance; D^2·D = D^3.

### Phase 2 — dual system generators (week 2–3)
- Generator A (direct; ground truth): transcribe Prop 4.3 verbatim. Unknowns = coeffs in the
  polygons; equations = coeffs of [P,Q] − x^2; saturate corner-nonvanishing (t·Πcorners·λ = 1);
  normalize the 2–3 dim torus (x,y,D scalings). Small code, hard to get wrong.
- Generator B (tower; the structure that makes S1 plausible): approximate root D = x^3 + Σ x^k d_k,
  d_k ∈ K[y] with valuation degree bounds; impose (D^2)_{-k} = 0, (D^3 + corrections)_{-j} = 0
  over auto-chosen truncation depth; back-substitute the linearly-entering d_k; emit residual
  functional identities; expand in y → small scalar system.
- Regression gate G0 (must pass before touching the open case):
  a) String-exact reproduction of the paper's residual identities:
     §5: 18·C3^23·d1·d−1^6·F−4 + 8·C3^69·F−4^3 + 27·d0·d−1^9 = 0   (eq. 5.9)
     §6: 9·y^9·d1·d−1^6 + y^27 + 27·d0·d−1^9 = 0                    (eq. 6.18)
  b) Auto-re-discard mod p of the solved cases: (66,99) [(9,24)], (72,108)#1 [(9,27)],
     (56,84) [(7,21)], and (50,75) via 1406.0886 §5.
  c) A vs B consistency: same emptiness/dimension/degree mod p on solved cases.

### Phase 3 — S1 verdict campaign on the open case (week 3–4)
S1 (defined): each branch (subcase × Pred-branch) finishes GB mod p on ≤192 vCPU/≤1.5TB in
≤12h, and the Q-level result lands in ≤5 days on one machine. Ladder:
- E1: Generator A, each branch, msolve over 3 random 62-bit primes. Record: finished?, max F4
  step degree, largest matrix, dim, degree. Empty at all primes for all branches → S1 nearly
  achieved → Phase 4. (Laptop-to-single-server scale; <$50.)
- E2: if dim ≥ 0: check whether positive dimension is truncation junk — deepen the imposed
  vanishing range (more P_{-k} = 0, Q_{-j} = 0 via Generator B's tower) and re-probe. Dimension
  should drop; if a 0-dim set survives, enumerate mod p, test side conditions.
- E3: if E1 blows up (>256GB or stalls at high step degree): switch to Generator B's reduced
  core (target: ≤ ~120 scalar unknowns after substitution + torus + forced-monomial shapes),
  re-probe mod p. Success here still counts as S1.
- E4 (verdict): S1 achieved = all branches empty (→ Phase 4) or 0-dim with side-condition
  checks cheap. S1 ruled out = both generators exceed the envelope mod p → S2 (1–4TB box,
  multimodular fan-out, $2k–15k) or new mathematics (further branch splitting; better
  elimination order; deeper valuation forcing à la their monomial-root arguments).

### Phase 4 — theorem-grade result (week 4+)
- Empty branch: msolve over Q; then Singular `lift(I,1)` → cofactor certificate; verify
  1 = Σ h_i f_i with the standalone FLINT checker (independent codebase, exact arithmetic).
  Optional stretch: Lean 4 reflection check of the certificate identity.
- Nonempty branch: RUR, exact side-condition checks. Any survivor = first live lead for a
  plane counterexample; publish the solution data regardless.
- Cross-checks either way: second GB engine mod p on final systems; HomotopyContinuation.jl
  on the torus-normalized bilinear formulation; two independent implementations of the
  system generators hashed and compared.
- Writeup: theorem (bound 108 → 125) or the live-lead analysis + artifact repo
  (systems, primes, certificates, checker, container).

## Effort & cost
One person fluent in both the GGV notation and CAS internals: 60–120 h to the S1 verdict.
Compute to verdict: <$100 (one c7a/Hetzner box; Apple Silicon fine for dev, x86 for runs).
Phase 4 in S1 world: <$200 total. Escalation envelope if S1 fails: $2k–15k (S2) before
declaring it math-bound (S3).

## Risks
- Derivation errors in Generator B → mitigated by G0 string-exact identities + A/B agreement.
- Solver bugs → dual engines + certificate independently checked.
- Junk positive dimension from too-shallow truncation → E2 auto-deepening.
- Reliance on Prop 4.3 & partially unrefereed chain → flagged; stretch: probe the full direct
  St(108,72)-type system mod p for independence from the corner reduction.
- Citation hygiene: arXiv and journal versions of the chain differ in at least one place —
  the published J. Algebra 471 (2017) version of 1401.1784 omits Cor. 7.12 (the computer-free
  "B = 16 or B > 20" gcd statement is arXiv-only; Heitmann JPAA 64 (1990) Thm 2.24 covers it
  independently). Pin exact arXiv versions in the writeup.
