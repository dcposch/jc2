## Purpose and ownership

Avoid serialized producer-then-checker authoring without shared mathematics.
After the source-wire FIRST passes, assign separate bounded owners:

- Producer owner: authority.py, arithmetic.py, produce.py.
- Independent checker owner: check_arithmetic.py, check.py.

Each works in its own named box, writes its own report/custody and changes no
other owner's files. Producer owns the common metadata interlock only; checker
may call its agreed API, not consume its live implementation. ROOT assembles
the five frozen sources for ONE combined different-model static FIRST after
both owners are independently complete. No scientific module is shared,
imported, copied or used as an oracle across the two new implementations.
The common metadata helper must contain no polynomial or finite-field code.

The source contract remains the literal full operation recipe plus adopted
corrections, the accepted rows-wire version and eventual focused-FIRST result.
Do not use the rational checker's Euler-fed bands or rational completion
comparison. All full internal expressions and diagnostic checks remain.

## Draft minimal metadata API

Propose retaining the old nine-argv convention, but with the NEW exact job tag
f10-source-cone-r3-direct-rows-v1 and separately approved new ROOT authorities:

python3 ENTRY --registered-job TAG --authorization META
  --authorization-sha256 META_SHA (--output PATH | --input PATH)

ENTRY is the actual installed produce.py or check.py, respectively. The
metadata helper independently verifies its caller's exact expected entry path;
passing mode alone must not make the checker entry a producer or vice versa.
Only authority.py may be imported before authorize returns; stdlib boot/imports
must remain covered by later ROOT native/startup registration. All scientific
imports, parsing of coefficient bodies and arithmetic occur AFTER authorization.
Mode is exactly produce or check, no diagnostic aliases.

authorize(mode) returns a plain mapping with exactly:
artifact_path, contract_sha256, source_pins, place.
artifact_path is the authorized absolute output/input path. The remaining
values are authenticated data, NOT mathematical verdicts. Both authors use
this same return API. No unchecked candidate chooses the place, source vector
or contract. For a checker candidate, the exact bytes/size/pin must be checked
before parsing. Producer target is UNFORMED and must not overwrite an existing
artifact; ROOT's actual output path and atomic publication are later bound.

Prospective metadata top keys are the old job_tag,status,authority,mode,
artifact,files,runtime,limits plus contract_sha256,source_pins,place.
Their status/authority remain REGISTERED/ROOT-CAPRUN, and artifact still has
path/sha256. files contains exactly the five scientific/metadata filenames
listed above with current installed hashes. The separately ROOT-issued
source_pins mapping binds those source files AND the literal contract/source
references required by the accepted wire; its final key set/vector is frozen
at actual registration, not invented or filled with placeholders in source.
Source hashes repeated there must agree with files. All pins are literal
64 lowercase hexadecimal strings, all mathematical numbers decimal strings.
No duplicate keys, floats, JSON numeric coercion or oversized metadata.

place is the prescribed p,degree,phi,P7_mod_p mapping. The helper only validates
its metadata shape/string container types and binds it to ROOT's immutable
metadata. It must not calculate primality, factor divisibility, field reduction
or leading coefficients. BOTH scientific implementations independently do all
those mathematical checks and exact comparison to ROOT's prescribed values.
contract_sha256 likewise authenticates ROOT's separate manifest, not a
self-generated candidate assertion or the helper's hash of arbitrary bytes.

The metadata loader/hash checks can reuse the accepted old authority design:
Linux/Amazon EC2 preflight, duplicate-key/number refusal, 64KiB metadata limit,
all five installed source hashes, interpreter pin and small matched native
subset. The last is NOT full ROOT native/startup closure or process custody.
No caller-created metadata becomes authority merely by hashing itself:
separately reviewed ROOT registration/launcher must issue and bind it.
