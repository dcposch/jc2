## 4. Exact ring, map, and localization custody

### 4.1 Source ideal

For a fibre with metadata variables
\((u_1,\ldots,u_N)\), source row polynomials
\(f_1,\ldots,f_r\in\mathbb Z[u_1,\ldots,u_N]\), and localization factor
`c`, the emitted modular ideal was

\[
 I_p=(\bar f_1,\ldots,\bar f_r, zc-1)
 \subset \mathbb F_p[v_1,\ldots,c,\ldots,v_{N-1},z].
\]

The rational confirmation input, if triggered, is the identical construction
in \(\mathbb Q[v_1,\ldots,c,\ldots,v_{N-1},z]\).  The variable `c` is never
added as a generator.  The equation `z*c-1` is the Rabinowitsch encoding of
the open set \(c\ne0\); omitting it, or adding `c`, would answer a different
question.

### 4.2 Name map and checks

`msolve_chart.py` reads the pipe-delimited `rows.tsv` and its metadata.  It
requires the exact header

```text
source_index|h_power|x_power|y_power|expr
```

and rejects a header-only file, a repeated header, a blank/malformed row, an
explicit zero generator, an identifier absent from the metadata ring, a
duplicate variable, or inconsistent saturation metadata.  Original names
containing underscores are mapped bijectively to msolve-safe names
`v1`, `v2`, ...; literal `c` is preserved; `z` is fresh and appended last.
Every translated polynomial is round-tripped through the inverse token map.
The manifest records, in order:

- source TSV, metadata, class JSON, and builder paths, sizes, and SHA-256s;
- original and safe variable order and every individual map pair;
- source-row and emitted-generator counts;
- emitted-field characteristic and emitter/package versions; the current
  schema also records source-row characteristic;
- literal localization polynomial `c`, slack `z`, and appended `z*c-1`;
- exact emitted bytes and SHA-256.

Four production manifests (`M6_13 V4_3`, `M2_9 V3_8`, `Mm12`, and `Mm15`)
predate the explicit `source_rows_characteristic` field.  They still hash the
exact characteristic-zero builder, its exact `rows.tsv`, metadata, and the
emitted target characteristic.  The late `M2_9 V1_8` manifest records source
characteristic zero explicitly.  Native finite-field TSVs have a distinct
path/provenance, and the current helper refuses to emit them under a different
source characteristic.

The production emitter is `msolveio.emit_system`; there is no hand-written
format fallback.  Adding `z` changes the solver variable counts from
77--378 to 78--379.  Adding `z*c-1` changes row counts from \(r\) to
\(r+1\).

The helper also supports manifest-recorded prefix or explicit-ordinal
subsets.  These were used only as one-way searches for a cheaper certificate:
if a selected subset plus `z*c-1` is the unit ideal over \(\mathbb Q\), then
the full ideal is unit.  A non-unit or timed-out subset says nothing about the
full ideal and is never labelled a surviving chart.

## 7. Exact-\(\mathbb Q\) promotion rule

An important msolve limitation changes how a characteristic-zero `[1]` must
be read.  In the deployed 0.6.5 binary, and also in the tested 0.10.1 binary,
`-g 2` may stop on a single modular prime when the first-prime Gröbner basis
is `[1]`; it does not expose a reconstructed rational cofactor certificate.
The local audit `xmodel/grok-msolve-erratum.md:47-119` documents the execution
path and a hidden-determinant example.  `qqideal.Ideal.verdict()` inherits
that behavior.  Consequently this lane types a characteristic-zero msolve
`[1]` as `UNIT_SIGNAL_MODULAR_ONLY`, not as an exact rational proof.

For every production unit signal the required promotion sequence is:

1. preserve the full input manifest and modular `[1]` output;
2. re-emit the selected generators from their original exact integer/rational
   rows, together with `z*c-1`, over characteristic zero--never lift a native
   finite-field TSV by changing its characteristic;
3. run msolve over the declared rational input as the requested check;
4. obtain an independent exact-\(\mathbb Q\) certificate, for example a
   Singular rational `std` result `[1]` on the same full ideal or on a
   manifest-recorded unit-generating subset.

Without step 4 the fibre remains `TIMEOUT/UNCONFIRMED`, regardless of how
many modular primes say unit.  Conversely, a completed non-unit modular basis
does not prove a rational point and is not a Keller pair.  A reported solution
would still have to be mapped back through the manifest, substituted into all
source rows and `z*c-1`, used to reconstruct `(P,Q)`, and checked exactly for
`J(P,Q)=c*x^ell` before it could be called a chart witness.  Lifting that
chart witness to a Keller pair is an additional theorem-sized requirement.
