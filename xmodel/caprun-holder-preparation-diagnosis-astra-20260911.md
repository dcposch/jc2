## What existing sequencing can and cannot remove

Existing behavior allows a fully reviewed skeleton, known worker bindings, command invariants, transfer destinations and release checklist to be prepared before holder admission. Only genuinely late fields need then be substituted. No new holder protocol is needed merely to reduce that work.

But holder.py only waits/checks/execs; final-install.sh only checks already-bound literals and installs already-formed documents. Neither serializes the registration, recomputes dependent authority digests, constructs the card/manifest, or performs ROOT's independent final-content review. The execution card explicitly places these duties on ROOT. Reordering these objects therefore cannot remove the late binding itself. A manual small delta is still manual composition within the same clock; an implicit new script is not existing reviewed behavior.

ONE smallest proposal, if ROOT separately opens a future cycle: review a fixed-schema late-binding renderer/checker for the already prepared documents and one authenticated observation record. It would allow only the enumerated holder/leaf substitutions and deterministic dependent hashes, reject all other changes, and produce complete candidate documents plus a compact difference/readback record. It would not create leaves, launch/install anything, approve itself, release the token, alter clocks, retry or change scientific code. ROOT must still independently read/authenticate the final result and explicitly approve release. This proposal is not implemented or licensed here and does not establish that the remaining observation/install/readback work fits120seconds.
